## Decisions
- Synthetic generation returns a dictionary of torch tensors (`series`, `graph`, `coefficients`); during a gradual switch the graph and coefficients interpolate linearly.
- RevIN uses population standard deviation over each window's time dimension.
- Graph sparsity regularization is the mean edge probability, and detector alerts temporarily boost the online graph optimizer's learning rate.
- Identity adjacency contributes node-local embeddings but masks the diagonal from cross-variable coupling; learned forecasts use EMA values with a straight-through gradient to current logits.
- Gate work: `tests/test_baselines.py` was already tracked, so the requested Step 0 staging/commit was unnecessary.
- Oracle fix: graph schedules are aligned to each window's last input step (`start + input_length - 1`); the old test schedule was one step late. Offline training/evaluation now groups windows by consecutive graph changes, so no batch crosses a graph regime and each graph is installed for its group. Online prequential forecasts install the matching graph before prediction. This also handles each distinct graph during a gradual blend without changing the SSM forward signature.
- Oracle graph metrics now compare the final evaluation graph with the true graph at the final evaluated window's last input time; a switching synthetic-run regression asserts zero SHD. Forecast-level schedule tests prove forecasts change with the supplied oracle graph.
- Environment finding: `configs/gate.yaml` and `configs/sanity.yaml` were present but untracked before this work. The run-config test now checks the required benchmark configs as a subset, so task-specific configs do not invalidate it.
- Oracle-fix acceptance: `pytest -q` passed all 28 tests (one pre-existing Transformer nested-tensor warning).
- Gate reporting: results now store per-window MSE and `switch_at`, `test_start`, and `input_length`. The reporter uses the first test window's last input index to compute pre/post-switch spans, then takes the first 200 and last 400 post-switch windows. Missing spans or unavailable graph metrics print as `-`.
- Graph reporting: identity and random variants explicitly report that graph metrics are unavailable because they have no trained logits; oracle scores use the time-matched graph. Learned-graph detection delay now uses the same last-input alignment as forecast graph selection, including a switch at the first test window.
- Gate-report acceptance: focused summary checks cover both 200/400 window boundaries and pre/post split alignment; `pytest -q` passed all 31 tests (one pre-existing Transformer nested-tensor warning). No dependency was added.
- Step 3 diagnostics: the exact `configs/sanity.yaml` run gave identity 0.019827 and oracle 0.019198 MSE (3.2% lower), triggering Step 4. The post-switch direct OLS table for horizons 1-6 is saved in `docs/DIAGNOSTICS.md`; full VAR mean MSE was 0.017155 versus 0.020414 per-variable AR and 0.020985 mean. The requested 4,000-step/40-epoch CPU run exceeded two minutes but completed within the ten-minute cap.
- Step 4 diagnosis (candidate a): multiplying `coupling_projection` initialization by 2 or 4 on a reduced 1,200-step run made oracle MSE diverge to 8.035167 and 2,085,796,315,136; scale 1 retained 0.017636 versus identity 0.017626. Initializing `logA` to -1 or -2 worsened oracle to 0.020249 or 0.169045 (identity 0.017685 or 0.017829). Rejected these initialization changes.
- Step 4 diagnosis (candidate b): a fixed scalar lag-input mix at scales 0.25/0.5/1.0 on reduced data yielded oracle MSE 0.017724/0.017895/0.018141 versus identity 0.017630/0.017680/0.017782, so fixed mixing was rejected. A zero-initialized learnable per-lag value mixer was then added and tested; reduced MSE was identity 0.017577, oracle 0.017288 (1.6% lower), and full sanity MSE was identity 0.019762, oracle 0.018919 (4.3% lower).
- Step 4 fix (candidate c/readout): added a zero-initialized, graph-masked direct per-horizon VAR readout, retaining the lag input mixer. Its edge/lag masking is covered by unit tests. On reduced data the MSE was identity 0.017493 and oracle 0.015497 (11.4% lower); on the full sanity run it was identity 0.019708 and oracle 0.017144 (13.0% lower), meeting the 10% criterion. This adds O(KD^2) lag mixing per input step and O(HKD^2) readout work per forecast (O(D^2) in D for fixed K,H), remains pure PyTorch, and does not change the SSM scan signature.
- Step 4 acceptance: full `pytest -q` passed all 33 tests (one pre-existing Transformer nested-tensor warning); the final sanity results are in `docs/DIAGNOSTICS.md`. No new dependencies were added.
- Graph-control decision: added `dense` with every off-diagonal edge enabled per lag. The prior random control sampled continuous `U[0,1]` edge weights for all `K D^2` entries (mean 0.5; 50% expected to exceed the 0.5 edge threshold), while the synthetic generator uses sparsity 0.2 at D=5 and 0.1 at D=20. Random now samples exactly `round(sparsity * D^2)` binary edges independently per lag, using the configured synthetic sparsity; the generator's realized counts can vary around that expectation. Complexity remains O(K D^2) per lag-graph resolution. Oracle graph input is now rejected outside oracle mode, and the model/leakage test checks true coefficients against forward inputs, buffers, and parameters.
- Perf step 1 (fast scan parity): `CausalSSMLayer` now keeps `_reference_forward` for equivalence tests and uses a fast path that precomputes graph features, `dt`, decay, gates, input projections, and output projections across all `L`, with only the recurrence inside the loop. `CausalSSM` also skips hidden-sequence materialization for single-layer stacks by calling `forward_last`. Parity tests compare forward outputs and gradients for all graph modes (`identity`/`dense`/`random`/`oracle`/`learned`), `D in {5,20}`, and batch sizes `{1,32}` with max abs diff `< 1e-5` in float64. CPU benchmark (`scripts/bench_speed.py`) before/after (`reference` -> `fast`): D=5 forward `4.634 -> 3.300 ms` (1.40x), backward `16.921 -> 11.194 ms` (1.51x), online `16.331 -> 7.925 ms/step` (2.06x); D=20 forward `6.632 -> 5.809 ms` (1.14x), backward `28.684 -> 28.326 ms` (1.01x), online `16.837 -> 9.103 ms/step` (1.85x).
- Perf step 2 (online overhead cuts): `GraphLearner.online_update` now skips autograd graph construction on non-`graph_stride` steps and uses `zero_grad(set_to_none=True)`. `train_online` now preallocates prediction/error tensors, computes running MSE via `torch.cumsum`, and returns optional tensors for callers to avoid list->tensor roundtrips; `run_experiment` consumes these tensors directly. Re-benchmark (`scripts/bench_speed.py`, `reference` -> `fast`): D=5 forward `4.912 -> 2.674 ms` (1.84x), backward `20.958 -> 12.653 ms` (1.66x), online `15.236 -> 7.956 ms/step` (1.92x); D=20 forward `6.481 -> 3.776 ms` (1.72x), backward `25.291 -> 27.394 ms` (0.92x), online `16.720 -> 8.294 ms/step` (2.02x).
- Quality step a (offline learned graph warm-start): added `warm_start_graph` to pretrain learned graph logits/VAR weights on the training split via structural loss before forecast optimization (default 5 epochs, configurable by `model.graph.warm_start_*`). On reduced h=6 ablations (`configs/quality_d5_h6.yaml`, `configs/quality_d20_h6.yaml`, seeds 17/18/19), learned validation MSE mean±std improved from `3.2440±4.5458` to `0.2594±0.3227` at D=5 and from `8.60e21±1.22e22` to `6.34e20±8.97e20` at D=20 when comparing warm-start epochs `0 -> 5`; learned graph AUROC improved from `0.5000±0.0000` to `0.6194±0.0235` (D=5) and `0.5208±0.0398` (D=20). Learned still underperforms identity on these reduced runs, so further quality work remains.
- Quality step b (validation threshold calibration): learned-graph metrics now support validation-calibrated thresholds via `model.graph.threshold_calibration` with modes `fixed_0.5`, `density_prior` (default), and `best_f1`. On reduced h=6 runs (seeds 17/18/19), `density_prior` improved SHD for D=20 from `152.0±7.1` (`fixed_0.5`) to `144.3±8.3` while preserving test MSE (unchanged because threshold affects metrics only); D=5 SHD stayed `13.7` while F1 rose from `0.2838±0.1084` to `0.3452±0.0541`. `best_f1` increased F1 but worsened SHD substantially, so it was not selected as default.
- Quality step d (stability controls): added optional `optimizer` (`adam`/`adamw`), `weight_decay`, `grad_clip_norm`, `lr_schedule` (`none`/`cosine`), `min_learning_rate`, and `early_stopping_patience` in training, plus optional `coupling_init_scale` for `CausalSSM` layers. On reduced h=6 runs (seeds 17/18/19, warm-start + density-prior threshold), switching from baseline settings to stabilized settings (`adamw`, `weight_decay=1e-4`, `grad_clip_norm=1.0`, `cosine`, `min_lr=1e-5`, `patience=3`, `coupling_init_scale=0.5`) changed learned validation MSE mean±std from `0.2594±0.3227` to `0.0234±0.0023` at D=5 and from `6.34e20±8.97e20` to `0.0220±0.0016` at D=20. Learned test MSE improved from `0.2544±0.3118` to `0.0260±0.0039` (D=5) and from `6.61e20±9.35e20` to `0.0225±0.0021` (D=20), now beating identity on both reduced settings.
- Stability step 1 (diagnosis, no model change): added `scripts/diagnose_stability.py` (+ `tests/test_diagnose_stability.py`, which checks the effective transition matrix against the brute-force recurrence) and the shrunk configs `configs/stability_d20.yaml` / `configs/stability_d5.yaml` (new names; `sanity*.yaml` untouched). On the shrunk D=20 run the oracle's one-step transition spectral radius is 2.011 at initialization versus 0.493 for identity, its hidden state hits 9.3e4 within one 24-step window, first-epoch loss is 3.4e6, and coupling/gate/input gradient norms are 6.6e9/1.0e9/2.0e9; lag mixer and readout row sums stay below 0.45. Cause: un-normalized cross-adjacency row sums (max 8, mean 4.35 at D=20 vs <= 3 at D=5) times `||coupling_projection||_2 ~ 0.97` times gate ~ 0.5. Also confirmed `sanity_d20.yaml` never sets `optimizer`/`grad_clip_norm`/`lr_schedule`, so the stabilized controls were not active in that config path. Details in `docs/DIAGNOSTICS.md` under "D=20 stability".
- Stability step 2a (fix, supported by the diagnosis): `CausalSSMLayer` now row-normalizes `cross_adjacency` by `max(1, row sum)`, rescales the coupling weight so its max absolute row sum is `<= coupling_norm_bound` (default 1.0, configurable as `model.coupling_norm_bound`), and multiplies the coupling term by `(1 - decay)`, so the one-step transition has absolute row sums `<= 1` and spectral radius `<= 1` for any D/density (unit test checks this on a dense D=20 graph with perturbed weights). The reference scan and fast scan were both updated; all 20 parity cases still pass. Shrunk D=20 seed 17: oracle init spectral radius 2.011 -> 0.517, hidden max 9.3e4 -> 0.47, first-epoch loss 3.4e6 -> 0.051, max coupling grad 6.6e9 -> 6.7e-4. Test MSE identity 0.024 -> 0.02397, dense inf -> 0.01812, random 0.42 -> 0.02310, oracle 2834 -> 0.02099, learned 9.9e10 -> 0.01816 (validation: identity 0.02646, oracle 0.02305). D=5 shrunk seed 17: identity 0.01917, oracle 0.01703, learned 0.01710, dense 0.01658, random 0.01867, none diverged. Lag mixer/readout row sums and `logA` were not implicated, so candidates (b) and (d) were skipped.
- Stability step 2c (training controls): `training.grad_clip_norm` now defaults to 1.0 in `run.py` for both offline and online paths (`null` disables; `test_grad_clip_defaults_on_and_can_be_disabled`). Verified the earlier stabilized controls were never enabled by `sanity_d20.yaml`. On shrunk D=20 seed 17 with fix 2a already in place, clipping changes nothing for dense/random/oracle/learned (0.01812/0.02310/0.02099/0.01816 test MSE unchanged) and moves identity 0.02397 -> 0.02417 test, 0.02646 -> 0.02672 val (noise level). Kept as a safety default; AdamW/warmup/weight-decay defaults were not adopted since the diagnosis does not implicate the optimizer.
- Stability step 3 (honest divergence flag): `run_experiment` now marks a variant `diverged: true` with a `divergence_reasons` list when (i) any value is non-finite (`non_finite_values`, previous behavior kept), (ii) test MSE or final validation MSE exceeds 10x the identity variant's (`test_mse_exceeds_10x_identity` / `validation_mse_exceeds_10x_identity`), or (iii) any epoch train loss (or online running MSE) exceeds 100x the first (`epoch_loss_exceeds_100x_first_epoch`). Under these rules the pre-fix D=20 run would have flagged random (0.42 vs identity 0.024), oracle, and learned as diverged, not just dense. Unit tests cover each reason and the end-to-end report.
