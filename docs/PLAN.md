## Decisions
- Synthetic generation returns a dictionary of torch tensors (`series`, `graph`, `coefficients`); during a gradual switch the graph and coefficients interpolate linearly.
- RevIN uses population standard deviation over each window's time dimension.
- Graph sparsity regularization is the mean edge probability, and detector alerts temporarily boost the online graph optimizer's learning rate.
- Identity adjacency contains only self-lags; synthetic truth, learned/random/oracle masks and the dense control all treat diagonal entries as legitimate lagged self-effects. Dense enables every (K,D,D) entry. CausalSSM uses reversible per-window RevIN for forecasting; the structural VAR objective sees raw values.
- Gate work: `tests/test_baselines.py` was already tracked, so the requested Step 0 staging/commit was unnecessary.
- Oracle fix: graph schedules are aligned to each window's last input step (`start + input_length - 1`); the old test schedule was one step late. Offline training/evaluation now groups windows by consecutive graph changes, so no batch crosses a graph regime and each graph is installed for its group. Online prequential forecasts install the matching graph before prediction. This also handles each distinct graph during a gradual blend without changing the SSM forward signature.
- Oracle graph metrics now compare the final evaluation graph with the true graph at the final evaluated window's last input time; a switching synthetic-run regression asserts zero SHD. Forecast-level schedule tests prove forecasts change with the supplied oracle graph.
- Environment finding: `configs/gate.yaml` and `configs/sanity.yaml` were present but untracked before this work. The run-config test now checks the required benchmark configs as a subset, so task-specific configs do not invalidate it.
- Oracle-fix acceptance: `pytest -q` passed all 28 tests (one pre-existing Transformer nested-tensor warning).
- Gate reporting: results now store per-window MSE and `switch_at`, `test_start`, and `input_length`. The reporter uses the first test window's last input index to compute pre/post-switch spans, then takes the first 200 and last 400 post-switch windows. Missing spans or unavailable graph metrics print as `-`.
- Graph reporting: learned, identity, dense, random, and oracle masks are all scored against the known graph at the last input timestamp; online learned history stores the pre-update EMA used by each forecast. Detector events carry the observation timestamp.
- Gate-report acceptance: focused summary checks cover both 200/400 window boundaries and pre/post split alignment; `pytest -q` passed all 31 tests (one pre-existing Transformer nested-tensor warning). No dependency was added.
- Step 3 diagnostics: the exact `configs/sanity.yaml` run gave identity 0.019827 and oracle 0.019198 MSE (3.2% lower), triggering Step 4. The post-switch direct OLS table for horizons 1-6 is saved in `docs/DIAGNOSTICS.md`; full VAR mean MSE was 0.017155 versus 0.020414 per-variable AR and 0.020985 mean. The requested 4,000-step/40-epoch CPU run exceeded two minutes but completed within the ten-minute cap.
- Step 4 diagnosis (candidate a): multiplying `coupling_projection` initialization by 2 or 4 on a reduced 1,200-step run made oracle MSE diverge to 8.035167 and 2,085,796,315,136; scale 1 retained 0.017636 versus identity 0.017626. Initializing `logA` to -1 or -2 worsened oracle to 0.020249 or 0.169045 (identity 0.017685 or 0.017829). Rejected these initialization changes.
- Step 4 diagnosis (candidate b): a fixed scalar lag-input mix at scales 0.25/0.5/1.0 on reduced data yielded oracle MSE 0.017724/0.017895/0.018141 versus identity 0.017630/0.017680/0.017782, so fixed mixing was rejected. A zero-initialized learnable per-lag value mixer was then added and tested; reduced MSE was identity 0.017577, oracle 0.017288 (1.6% lower), and full sanity MSE was identity 0.019762, oracle 0.018919 (4.3% lower).
- Step 4 fix (candidate c/readout): added a zero-initialized, graph-masked direct per-horizon VAR readout, retaining the lag input mixer. Its edge/lag masking is covered by unit tests. On reduced data the MSE was identity 0.017493 and oracle 0.015497 (11.4% lower); on the full sanity run it was identity 0.019708 and oracle 0.017144 (13.0% lower), meeting the 10% criterion. This adds O(KD^2) lag mixing per input step and O(HKD^2) readout work per forecast (O(D^2) in D for fixed K,H), remains pure PyTorch, and does not change the SSM scan signature.
- Step 4 acceptance: full `pytest -q` passed all 33 tests (one pre-existing Transformer nested-tensor warning); the final sanity results are in `docs/DIAGNOSTICS.md`. No new dependencies were added.
- Graph-control decision: random samples exactly `round(sparsity * D^2)` binary edges independently per lag, including self-lags, using the configured synthetic sparsity. Dense includes all entries to share the same self-lag convention; identity contains only self-lags.
- Correctness audit (2026-10-29): baseline in the local copy was 36 tests passing and `results/baseline_synthetic_abrupt.json` (seed 17, MSE 0.143124, graph AUROC 0.978175). The baseline online loop immediately trained on all six horizon labels and is not comparable to the corrected delayed-label protocol.
- Correctness regressions added first: offline graph VAR weights/logits/EMA updates, late-label perturbation isolation, pre-update graph snapshots/timestamps, variant order independence, and train-only warm starts.
- Corrected training ownership: forecast optimizers exclude GraphLearner parameters; offline structural fitting and online structural updates use the graph learner's optimizer. Forecasts consume EMA probabilities without straight-through gradients. Offline learned adjacency is no longer silently left at initialization.
- Corrected online timing: label at horizon h is consumed only once its timestamp is within the current observed input window; delayed replays install the matching historical oracle graph. Online protocol is explicitly cold-start (default) or train-only warm-start, shared by every configured variant.
- Evaluation correctness: seeds are applied before each variant is constructed; graph masks are scored at each forecast's last-input timestamp; online masks are captured before their update. CPU adaptation metrics explicitly compare CPU copies so CUDA tensor placement cannot cause device-mismatch failures.
- Stability and normalization audit: every generated blended VAR frame is checked against companion spectral radius 0.89 and rescaled only if needed; CausalSSM now applies/inverts per-window RevIN while graph structural learning remains on raw values. On three development seeds the largest checked radius was 0.793979 for D=5,K=2 and 0.787355 for D=20,K=2.
- Correctness acceptance: `pytest -q` passed 51 tests (one existing Transformer warning), including DirectVAR, graph/readout/coupling/update ablation wiring, and fail-fast handling of non-finite forecast, loss, gradient, and parameter values. The corrected seed-17 abrupt online run completed with 202 timestamp-aligned graph metric rows, test MSE 2.3445296, graph AUROC 0.938492; this is one cold-start run, not evidence of model contribution. Timestamp verification uses input-observation indices 304 through 505.
- `scripts/graph_diagnostics.py` completed stationary D=5 and D=20 at three fixed data/model seed pairs, with validation-only edge threshold selection, empty/dense/random controls, and a fitted sparse VAR reference. `results/graph_diagnostics.json` and per-epoch optimizer/shuffle checkpoints in `results/graph_diagnostics_checkpoints/` preserve all six runs.
- Stationary synthetic graph-recovery summary (mean ± population SD): at D=5 learned F1 0.9740±0.0187, SHD 0.67±0.47, AUROC 1.0000±0.0000; sparse VAR F1 1.0000±0.0000, SHD 0.00±0.00. At D=20 learned F1 0.9855±0.0138, SHD 2.33±2.05, AUROC 0.9999±0.0001; sparse VAR F1 0.9983±0.0025, SHD 0.33±0.47. This supports recovery on the generator's stationary graph, not causal discovery from observational real-world data.
- Matched model contribution/ablation gate: all 9 scenario/data-seed/model-seed runs completed across 14 variants and 202 test windows each. The 79m26s CPU campaign, run ledger, exact per-run configs/hashes, environment metadata, raw JSON, summary CSV/JSON, plots, and environment lock are under `results/model_contribution/`. Learned-variant replays saved all 202 pre-update EMA graph snapshots for each run and verified forecast and graph metrics against the campaign results.
- Research conclusion: learned forecasting did not beat identity, oracle, DLinear, or no-SSM-coupling in any regime mean. Learned MSE was 35.1531 ± 60.8271 stationary, 35.1049 ± 60.7452 abrupt, and 35.1498 ± 60.8243 gradual; these large means are dominated by seed 303's finite cold-start spike (per-window MSE 6,967.57), which was preserved without clipping. Dense MSE was about 534.5 ± 925.8 in every regime. The no-SSM-coupling ablation remained near 0.013, identifying the coupling path as a follow-up diagnostic lead, not a proven mechanism. Detector events occurred in 0/3 abrupt seeds and 1/3 gradual seeds (79-step delay); these results do not support model contribution or adaptation claims.
